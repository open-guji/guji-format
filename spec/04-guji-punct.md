# guji-punct 规范：独立外挂标点格式 (v0.1)

> 格式标识符：`https://open-guji.org/schema/punct/v0.1`  
> 推荐扩展名：`*.punct.json`

---

## 1. 设计初衷与原则

古籍在底本物理形态中通常无标点（或仅有极少数圈点、句读符号）。现代古籍整理的核心工作之一是**新式标点**（句号、逗号、顿号、引号、专名号/书名号等）。

传统将标点直接内嵌正文的做法存在以下硬伤：
1. **字符位移与版本冲突**：标点嵌入改变了字符索引，底本若校勘出一个讹误字，或者修正了异体字，嵌入标点的整个文本全文 diff 都会被污染。
2. **多整理本冲突**：不同学者、不同整理本、不同大模型对同一篇文言文的断句和标点存在分歧（例如句意两可之处）。若内嵌正文，必须克隆多份完整底本正文，造成海量冗余。
3. **字形正交性受损**：原字、繁体、简体三种字形转换时，若夹杂标点，容易误伤或干扰繁简词组匹配。

**解决方案：标点与正文 100% 解耦**：
- **只存锚点**：标点文件只记录“在哪个字符后面（或跨哪段字符区间）施加什么标点”；
- **只读底本**：底本正文保持绝对纯净；
- **热插拔与多标本并存**：可以同时存在 `qwen-plus.punct.json`、`wikisource.punct.json`、`expert-proof.punct.json`，在渲染时按需动态加载合成。

## 2. 锚点定位策略

`guji-punct` 支持两种粒度的字符锚点：

### 2.1 基于拓扑格位锚点（Level 2 Cell 锚点，强推荐）
格式：`<页>:<列>:<格>[子列]`，如 `3:5:12`（在单册文件内天然独立，省略册号；跨册深链才扩展为 `v<册>/<页>:<列>:<格>`）
- **超框抬头**：若遇抬头超出上框，格位使用负数标定，如 `3:5:-1` 或 `3:5:-2`。
- **优点**：即使全书删改了一段错简或插页，单列内的格位标点依然精准无误，极其鲁棒。
- 支持夹注子栏（如 `3:5:12a` 表示夹注右栏，`3:5:12b` 表示夹注左栏）。

### 2.2 基于线性字符流位移锚点（Level 3 Markdown 锚点）
格式：`{"page": 3, "char_index": 128}` 或篇章全局 `{"char_offset": 1024}`
- **优点**：直接与渲染后的自然段/页面文本一一对应，计算与合成极其高效。
- **保护约束**：字符偏移量**严禁计算空格与换行**，仅计算非空白的实体文字字符，确保格式重排（换行/缩进）时不影响锚点定位。

## 3. 数据模型定义

### 3.1 单个标点条目（Punctuation Entry）

标点分为三大类：
1. **点号（Point Marks）**：句号 `。`、逗号 `，`、顿号 `、`、分号 `；`、冒号 `：`、问号 `？`、感叹号 `！`、破折号 `——`、省略号 `……`。
   - 插入在某个字符的**紧随其后**（`after`）。
2. **篇章分段控制符（Structural Breaks）**：自然段分段符 `\n\n`（`paragraph_break`）。
   - **核心设计**：分段符在语义上本质是篇章级的高阶断句标记。作为一等公民与句点并列，指示在此字之后结束自然段落。
   - 若外挂文件只加载点号不加载分段符，渲染为原刻分行版；若同时加载分段符，渲染为自然段落版。
3. **标号/区间标点（Range Marks）**：引号 `「」`/`“”`、书名号 `《》`、专名号（下划线）、括号 `（）`。
   - 作用于连续的**字符区间**（`start_after` 到 `end_after`，或者带 `start` 与 `end` 字符锚点）。

```json
{
  "id": "p001",
  "mark": "，",
  "kind": "point",
  "pos": "after",
  "anchor": {
    "page": 3,
    "line": 1,
    "slot": 4
  },
  "char_offset": 24,
  "pre_char": "帝",
  "confidence": 0.95,
  "source": "llm:qwen-plus"
}
```

分段符条目示例：
```json
{
  "id": "b001",
  "mark": "\n\n",
  "kind": "break",
  "pos": "after",
  "anchor": "3:3:1:10",
  "char_offset": 10,
  "pre_char": "四",
  "confidence": 0.98,
  "source": "llm:qwen-plus"
}
```

字段说明：
- `mark`: 标点符号（使用 Unicode 中文标点字符，如 `，`、`。`、`「`、`」`、`《`、`》`）。
- `pos`: 插入位置，取值 `after`（默认，插入在该字符后）、`before`（插入在该字符前，常用于开引号/前书名号）、`range`（区间，如书名号包裹）。
- `anchor`: 拓扑格位定位（可选，推荐包含 `page`, `line`, `slot`）。
- `char_offset`: 篇章或页面内的纯文字偏移量（从 0 或 1 开始，由上下文定义）。
- `pre_char`: **安全校验字**（Crucial！）。记录锚点位置前一个字符是什么（例如 `帝`）。合成器在注入标点前必须校验底本对应位置是否确实为该字符，若字形不一致则触发告警或对齐修复，防止因文本版本微调导致标点错位。
- `confidence`: 标点置信度（0.0 ~ 1.0），LLM 生成或人工打标。
- `source`: 来源标识（例如 `human:lisdp`、`llm:qwen-plus`、`rule:pattern`）。

## 4. 动态合成与阅读器接入规范（Reader Implementation）

标点与文本的结合遵循**纯流式单向注入（Merge Injection）**，阅读器和排版引擎统一遵循以下流程：

### 4.1 双模式渲染规范
- **模式 1：自然段现代阅读版（`reflow`）**：
  - 遇到 `kind: "point"`（句逗、书名号等），插入字符流对应位置；
  - 遇到 `kind: "break"`（`mark: "\n\n"`），在该字之后闭合当前自然段，输出段落换行；
  - 忽略底本行末换行，保留 `<!-- pN -->` 影像页码锚点。
- **模式 2：原刻分行带标点版（`lines`）**：
  - 遇到 `kind: "point"`，插入字符流对应位置；
  - **忽略 `kind: "break"` 分段符**；
  - 严格保持底本每列换行、行首抬头 `^` 与挪抬 `.`。

### 4.2 逐字流式注入算法
1. **读取底本纯文本流**：
   从 Level 3a (`lines.md`) 或 Level 3b 提取底本实体文字流（跳过 `<!-- pN -->` 等控制标记）。
2. **标点流映射与排序**：
   按 `char_offset` 或拓扑 `anchor` 升序排列标点。
3. **逐字遍历与安全防御校验**：
   - 设当前字符流指针为 $i$；
   - 若当前位置存在 `pos: "before"` 标点（如前引号），先输出标点；
   - 输出底本字符 $text[i]$；
   - 若匹配 `pos: "after"` 标点：
     - **防御校验**：校验 $text[i] == pre\_char$；
     - 若校验通过，将标点字符或分段符压入输出流；
     - 若字形不一致，触发警告并在前端标红存疑，避免盲目错位。
4. **输出富渲染 HTML/Markdown**：
   阅读器根据注入后的流直接渲染竖排/横排视图。
