# guji-punct 规范：独立外挂标点格式 (v0.1)

> 格式标识符：`https://open-guji.org/schema/punct/v0.1.json`  
> 推荐扩展名：`*.punct.json`

---

## 1. 设计初衷与原则

古籍在底本物理形态中通常无标点（或仅有极少数圈点、句读符号）。现代古籍整理的核心工作之一是**新式标点**（句号、逗号、顿号、引号、专名号/书名号等）。

传统将标点直接内嵌正文的做法存在以下硬伤：
1. **字符位移与版本冲突**：标点嵌入改变了字符索引，底本若校勘出一个讹误字，或者修正了异体字，嵌入标点的整个文本全文 diff 都会被污染。
2. **多整理本冲突**：不同学者、不同整理本、不同大模型对同一篇文言文的断句和标点存在分歧（例如句意两可之处）。若内嵌正文，必须克隆多份完整底本正文，造成海量冗余。
3. **字形正交性受损**：原字、繁体、简体三种字形转换时，若夹杂标点，容易误伤或干扰繁简词组匹配。

**解决方案：标点与正文 100% 解耦**：
- **只存锚点**：标点文件只记录“在哪个字符后面（或跨哪段字符区间）施加什么标点”；
- **只读底本**：底本正文保持绝对纯净；
- **适用范围**：本格式只给 book-text 的 `original`（本项目从书影做出来的文本）用。维基文库、Kanripo、识典等转录导入一次就不再改，以后由 `original` 覆盖，不做外挂标点。
- **每册一份**：入库的只有一份 `NNN.punct.json`（`NNN` 是章号）。几个模型的对照稿只在本地测试，不进仓。

## 2. 锚点定位策略

`guji-punct` 支持两种粒度的字符锚点：

### 2.1 基于拓扑格位锚点（Level 2 Cell 锚点，强推荐）
格式：`<页>:<列>:<格>[子列]`，如 `3:5:12`（在单册文件内天然独立，省略册号；跨册深链才扩展为 `v<册>/<页>:<列>:<格>`）
- **超框抬头**：若遇抬头超出上框，格位使用负数标定，如 `3:5:-1` 或 `3:5:-2`。
- **优点**：即使全书删改了一段错简或插页，单列内的格位标点依然精准无误，极其鲁棒。
- 支持双行夹注子列：`3:5:12a` 是夹注右列（先读），`3:5:12b` 是左列（后读），两列各自从同一格起数。`lines.md` 里 `<甲|乙>` 的甲是右列，乙是左列。

### 2.2 基于线性字符流位移锚点（Level 3 Markdown 锚点）
格式：`{"page": 3, "char_index": 128}` 或篇章全局 `{"char_offset": 1024}`
- **优点**：直接与渲染后的自然段/页面文本一一对应，计算与合成极其高效。
- **保护约束**：字符偏移量**严禁计算空格与换行**，仅计算非空白的实体文字字符，确保格式重排（换行/缩进）时不影响锚点定位。

## 3. 数据模型定义

### 3.1 单个标点条目（Punctuation Entry）

标点分为三大类：
1. **点号（Point Marks）**：句号 `。`、逗号 `，`、顿号 `、`、分号 `；`、冒号 `：`、问号 `？`、感叹号 `！`、破折号 `——`、省略号 `……`。
   - 插入在某个字符的**紧随其后**（`after`）。
2. **篇章分段控制符（Structural Breaks）**：自然段分段符 `\n\n`（`paragraph_break`）。
   - **核心设计**：分段符在语义上本质是篇章级的高阶断句标记。作为一等公民与句点并列，指示在此字之后结束自然段落。
   - 若外挂文件只加载点号不加载分段符，渲染为原刻分行版；若同时加载分段符，渲染为自然段落版。
3. **成对标号（Paired Marks）**：引号 `「」`／`『』`、书名号 `《》`、括号 `（）`。
   - 拆成两条点号记：开符号 `pos: "before"`，锚在区间第一个字；闭符号 `pos: "after"`，锚在区间最后一个字。`kind` 都写 `point`。`kind: "range"`、`pos: "range"` 保留不用。
   - **书名号两层都记**：大模型识别出的书名，在本层出一对 `《》`，同时在实体层（[05](./05-guji-entity.md)）出一个 `work` 实体，挂 book-index 的 id；`《` 的锚点必须等于该实体的 `anchor.start`，`》` 的锚点必须等于 `anchor.end`。
   - 专名号（人名、地名等的下划线）只在实体层记，本层不记。

```json
{
  "id": "p001",
  "mark": "，",
  "kind": "point",
  "pos": "after",
  "anchor": "3:1:4",
  "char_offset": 24,
  "pre_char": "帝",
  "confidence": 0.95,
  "source": "llm:qwen-plus"
}
```

分段符条目示例：
```json
{
  "id": "b001",
  "mark": "\n\n",
  "kind": "break",
  "pos": "after",
  "anchor": "3:3:10",
  "char_offset": 10,
  "pre_char": "四",
  "confidence": 0.98,
  "source": "llm:qwen-plus"
}
```

字段说明：
- `mark`: 标点符号（使用 Unicode 中文标点字符，如 `，`、`。`、`「`、`」`、`《`、`》`）。
- `pos`: 插入位置，取值 `after`（默认，插入在该字符后）、`before`（插入在该字符前，常用于开引号/前书名号）。成对标号拆成 before／after 两条（见上），`range` 保留不用。
- `anchor`: 拓扑格位，字符串 `<页>:<列>:<格>[子列]`（见 §2.1）。`original` 入库的文件一律用字符串；对象写法 `{page, line, slot}` 只为兼容旧数据保留。
- `char_offset`: 篇章或页面内的纯文字偏移量（从 0 或 1 开始，由上下文定义）。
- `pre_char`: **安全校验字**（Crucial！）。记录**锚点那一格上的字**（例如 `帝`）：`after` 标点是这个字后面的标点，`before` 标点（开引号、`《`）是这个字前面的标点，两种都核锚点格上的字。合成器在注入标点前必须校验底本对应位置是否确实为该字符，若字形不一致则触发告警或对齐修复，防止因文本版本微调导致标点错位。
- `confidence`: 标点置信度（0.0 ~ 1.0），LLM 生成或人工打标。
- `source`: 来源标识（例如 `human:lisdp`、`llm:qwen-plus`、`rule:pattern`）。

## 4. 动态合成与阅读器接入规范（Reader Implementation）

标点与文本的结合遵循**纯流式单向注入（Merge Injection）**，阅读器和排版引擎统一遵循以下流程：

### 4.1 双模式渲染规范
- **模式 1：自然段现代阅读版（`reflow`）**：
  - 遇到 `kind: "point"`（句逗、书名号等），插入字符流对应位置；
  - 遇到 `kind: "break"`（`mark: "\n\n"`），在该字之后闭合当前自然段，输出段落换行；
  - 忽略底本行末换行，保留 `<!-- pN -->` 影像页码锚点。
- **模式 2：原刻分行带标点版（`lines`）**：
  - 遇到 `kind: "point"`，插入字符流对应位置；
  - **忽略 `kind: "break"` 分段符**；
  - 严格保持底本每列换行、行首抬头 `^` 与挪抬 `.`。

- 顶层 `volume` 是册号，等于 book-text `original/index.json` 里该章的 `n`（`volume: 2` ↔ `002.punct.json`）。
- `stats` 只是统计，键名不限，值为整数；常用 `total_annotations`、`points`、`paragraph_breaks`、`periods`、`commas`。

### 4.2 逐字流式注入算法
1. **读取底本纯文本流**：
   从 Level 3a (`lines.md`) 或 Level 3b 提取底本实体文字流（跳过 `<!-- pN -->` 等控制标记）。
2. **标点流映射与排序**：
   按 `char_offset` 或拓扑 `anchor` 升序排列标点。
3. **逐字遍历与安全防御校验**：
   - 设当前字符流指针为 $i$；
   - 若当前位置存在 `pos: "before"` 标点（如前引号），先输出标点；
   - 输出底本字符 $text[i]$；
   - 若匹配 `pos: "after"` 标点：
     - **防御校验**：校验 $text[i] == pre\_char$（`before` 标点在输出 $text[i]$ 之前做同样校验）；
     - 若校验通过，将标点字符或分段符压入输出流；
     - 若字形不一致，触发警告并在前端标红存疑，避免盲目错位。
4. **输出富渲染 HTML/Markdown**：
   阅读器根据注入后的流直接渲染竖排/横排视图。

## 5. 版本号（book-text `original`，2026-10-05 定）

> 规范全文：open-guji-core/overview `项目进展/古籍文本/整体设计/2026-10-文本版本号与仓库流程.md`（v2）。

本格式文件顶层的 `version` 是**本层的内容版本**，不是格式版本（格式版本看 `$schema`）。

### 5.1 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `version` | 是 | 本层（标点）的内容版本，`MAJOR.MINOR.PATCH`；MAJOR 只能是 0–3（0 只用于 wip，1–3 是质量等级） |
| `text_version` | 是 | 本层是对着哪一版文本做的，即 book-text `original/index.json` 该章的 `text_version`。**不得超前于当前文本** |
| `review` | major ≥2 时必填（schema 强制） | 验收记录，`date`、`signed_by`、`sample`（抽检数据）三项都不许为空 |

```json
{
  "$schema": "https://open-guji.org/schema/punct/v0.1.json",
  "version": "1.2.0",
  "text_version": "1.4.1",
  "book_id": "96mid1ogzk"
}
```

### 5.2 三线独立

本格式只用于 book-text 的 `original`（见 §1），所以这几个字段都必填。`original` 每册分三条线，各自独立的 semver，互不牵连：

| 线 | 文件 | 版本号记在 |
|---|---|---|
| 文本 | `NNN.lines.md` | `original/index.json` 章条目的 `text_version` |
| 标点 | `NNN.punct.json`（[04](./04-guji-punct.md)） | 顶层 `version` |
| 实体 | `NNN.entity.json`（[05](./05-guji-entity.md)） | 顶层 `version` |

文本改了以后，逐个核本层锚点的校验字（`anchor` 所指格位的字与 `pre_char` 是否一致）：

- 全对得上：本层只把 `text_version` 跟到新文本版本，**不升**自己的 `version`；
- 有对不上的：本层按规模修，修好后自己升 patch 或 minor，`text_version` 同时跟上。

### 5.3 三级怎么升

- **major ＝ 质量等级**：1 可用，2 出版级，3 定本。门槛从严，绝大多数停在 1；升 major 要成文验收记录（`review`），并要用户点头；脚本不自动升。major 一升，minor、patch 归零。
- **minor ＝ 较大改动**：整册重跑或换模型、换提示词；新的分段规则；新增标点类型（如引号分层）；批量修正一类错误（如「曰」后统一加冒号）。
- **patch ＝ 小范围改动**：改几处、几十处标点；修少量锚点没对上的条目。
- **分界**：以一次 PR 为单位，一册改动 ≤50 处且逐处改的算 patch；超过，或按规则成批改的算 minor。拿不准选 minor。
- **本层 major 不得高于文本线的 major**：文本还没到出版级，标点也不能先升。
- `wip/` 阶段可写 `0.x`；第一次并入 book-text main 时定为 `1.0.0`，前提是够得上第 1 级。

### 5.4 major 门槛（标点线）

| 等级 | 门槛 |
|---|---|
| 1 可用 | 机器标点（LLM），只插标点、不改字；抽 200 处，一致率 ≥95% |
| 2 出版级 | 全册人工审读一遍，书名号、引号层级、分段符合标点规范；抽 500 处，一致率 ≥99.5% |
| 3 定本 | 对照至少一种权威点校本逐段核过，分歧处有记录和取舍理由；抽 1,000 处，一致率 ≥99.9%；用户签核 |
