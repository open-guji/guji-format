## 0. 通用规则

### 0.1 不生效区（inert regions）

按从外到内的顺序，下列区域内的字符**一律按字面处理**，不进行任何扩展识别：

1. **围栏代码块** —— ``` 或 `~~~` 开启，直到同类型、长度不小于开启栏的围栏。
2. **缩进代码块** —— 空行之后、（去除块引用标记后）缩进 ≥ 4 个空格的行，
   直到下一个空行后不再满足缩进为止。
3. **代码片段** —— 反引号串 `` ` ``…`` ` ``，遵循 CommonMark 的等长匹配规则。
4. **原始 HTML 标签与自动链接** —— `<div …>`、`</p>`、`<!-- … -->`、
   `<https://…>`、`<name@example.com>` 的**整体**。
5. **行内链接 / 图片的目标** —— `](` 起，到配对的 `)` 止（含标题部分）。
6. **反斜杠转义** —— `\` 加一个 ASCII 标点，两字符整体不可见于扩展扫描。

> **实现提示**　推荐做法是先构造一条与源文等长的"掩码串"，
> 把上述区域的字符置为 NUL，之后所有记号匹配都在掩码串上做、输出时取原串。
> 这样索引天然对齐，且不必回溯。

### 0.2 行内记号不跨行

夹注、补字、删字、改字、专名号、书名号的**起止记号必须位于同一行**。
换行即视为该记号未闭合，按字面输出。

这条规则同时解决了两类歧义：`>` 在行首是块引用标记而非夹注结束；
`《` 落在行尾时不会吞掉下一行。

### 0.3 未闭合即字面

任何起始记号如果在本行内找不到合法的结束记号，整段按普通文本输出，不报错。

### 0.4 长度上限

行内记号的内容超过长度上限时**视为未闭合**（即按 §0.3 整段按字面输出）。
上限用于避免误匹配把整行吞掉。

默认上限**按记号分设**：

| 记号 | 默认上限 |
| --- | --- |
| 夹注 `<…>` | **4096** |
| 补字 `((…))`、删字 `{{…}}`、改字 `[…]`、专名号 `/…/`、书名号 `《…》`、阙文 `[[…]]` | **64** |

之所以不是一个数，是因为**上限的收益与代价按记号而异**：

* 书名、专名、改字的内容**天然短**，而它们的起止记号同形（`/…/`）或极易
  被 OCR 讹字打乱（`《` 误作 `(`、`》` 误作 `)`），误配对风险高——
  上限是有效的防呆，64 已给出数倍余量。
* 夹注恰好相反。古籍的双行小字注**天然可以很长**（书目提要、注家案语动辄
  数百字），而 §1 给了它一组很严的起始条件（`<` 之后不得是 ASCII 字母、
  `/`、`!`、`?`、`>`、空白），误配对风险本就极低——
  对夹注设一个小上限，只有代价，没有收益。

> **实测依据**　在一批 1,870 个文件的古籍整理本语料上：夹注内容最长 3,212 字、
> 第 99 百分位 268 字；书名号内容第 99.9 百分位仅 20 字。若夹注沿用 64，
> 该语料中有 **1,979 处**夹注会静默变成正文；而把 64 用在其余记号上，
> 恰好挡下 31 处误配对（OCR 讹字、抓取残留的 HTML 片段），
> 只误伤 6 处把卷数写进了书名号的超长书名。

实现可用 `maxSpanLength` 覆盖：给**一个数**则七种记号一律用它（不留隐藏例外），
给**一个表**则按记号分设、缺项落到 `default`。

```ts
gujiToDirective(src, { maxSpanLength: 200 })            // 七种一律 200
gujiToDirective(src, { maxSpanLength: { jz: 8192 } })   // 夹注 8192，其余 64
```

### 0.5 ⚠️ 降级必须可数

§0.3 规定未闭合**不报错**。长度上限因此是本规范里唯一会**静默改变输出**的
机制：超限的夹注不会变成错误，会变成正文——不报错、退出码为零、
只是产出的记号数悄悄变少。

所以规范要求：**实现可以静默降级，但不得让降级本身无法统计。**
凡因超过长度上限而被降级的记号，实现必须提供一条途径让调用方数出
「有几处、在哪一行、原本多长」。批量转换存量文本时，这是唯一能发现
「有内容悄悄变成正文」的办法。

本仓的做法是 `onOverflow` 回调与 `gujiToDirectiveWithReport`：

```ts
const { text, overflows, overflowCounts } = gujiToDirectiveWithReport(src)
if (overflows.length) throw new Error(`有 ${overflows.length} 处记号被降级为正文`)
```

事件里带 `mark`、`line`、`column`、`length`、`limit`、`preview` 六项，
指得回源文。注意**只有「本可成立却因超长而作罢」才算降级**：
压根没有配对的起始记号、被 `requireCjk` 挡掉的、落在不生效区里的，
都属于正常的按字面处理，不计入。

## 1. 夹注（小注）`<…>`

古籍正文中的双行小字注。

```markdown
子曰<孔子也>：學而時習之，不亦說乎<悅也>。
```

→

```markdown
子曰:jz[孔子也]：學而時習之，不亦說乎:jz[悅也]。
```

### 生效条件

`<` 作为夹注起始，必须同时满足：

| # | 条件 | 目的 |
| --- | --- | --- |
| 1 | `<` 不在不生效区内 | 见 §0.1 |
| 2 | 紧随其后的字符**不是** ASCII 字母、`/`、`!`、`?`、`>`、空白 | 避开 HTML 标签、闭合标签、注释、自动链接 |
| 3 | 本行内存在配对的 `>` | 见 §0.2 |
| 4 | 内容非空且长度 ≤ 上限 | 见 §0.4 |

`<` 与 `>` **可嵌套**（`<注<再注>>`），按计数配对。

### 反例

```markdown
a < b 且 b > c        ← 条件 2 失败（`<` 后为空白），按字面
<div>正文</div>        ← 条件 2 失败，仍是原始 HTML
<https://example.com> ← 条件 2 失败，仍是自动链接
`<注>`                 ← 在代码片段内，按字面
```

需要在正文里写真正的尖括号时用 `\<`。

### 分行 `|`

古籍的双行小字注排版时常常按原书分成两行。夹注内容里的字面 `|`
是这个分行点，长写法为 `:jz[…]`：

```markdown
子曰<孔子也|魯人>
```

→ `子曰:jz[孔子也|魯人]`

**只在夹注内生效**：`|` 只有落在 `<…>`（或 `:jz[…]`）的内容里才是分行点；
夹注之外的 `|` 一律按字面处理，不做任何转换（本规范不使用管道表，
参见 [12. 保留与未来扩展](#12-保留与未来扩展)）。

**渲染**：横排默认**忽略**这个分行点（注文仍连排成一段，不出现可见换行）；
竖排、或需要还原原书分行的场合，渲染器按它把注文分成两行显示。
两种都不改变纯文本输出（[ast.md §3](./ast.md#3-纯文本输出)）。

**在 `:::table` 表格容器（[§15](#15-表格容器-table)）的格子内，`|` 是分格符**，
格内若要写带分行的夹注，`|` 必须转义成 `\|`：

```markdown
:::table
甲 | 乙<丙|丁> | 戊
:::
```

夹注内的分行效果不受影响（转义只是为了不被表格的分格逻辑先一步拆开），
渲染出来仍然是两行注文。

## 2. 补字 `((…))`

整理者**新增**的文字——底本没有，据他本或文义补入。

```markdown
帝曰((朕))知之矣。
```

→ `帝曰:bz[朕]知之矣。`

### 生效条件

* `((` 与 `))` 在同一行，可嵌套；
* 内容非空且长度 ≤ 上限；
* 不在不生效区内。

单个 `(` `)` 无特殊含义。`((` 紧接在 `]` 之后（即 `](`）时按链接目标处理，不识别为补字。

---

## 3. 删字 `{{…}}`

整理者认为**衍出、应删**的文字——底本有，定本无。

```markdown
帝曰知{{之}}之矣。
```

→ `帝曰知:sz[之]之矣。`

生效条件同 §2。单个 `{` `}` 无特殊含义——注意这一点使指令属性 `{n=1}` 不会被误判。

> **与模板语法的冲突**　`{{ }}` 在 Vue / Handlebars 等模板中另有含义。
> 古籍文本一般不涉及；确需字面双花括号时用 `\{\{`。

## 4. 改字 `[…]`

整理者**校改后的文字**——它替换掉紧随其后被删的原文，
所以既不是"凭空新增"，也不是"单纯删去"。

```markdown
原作[甲]{{乙}}。
```

→ `原作:gz[甲]:sz[乙]。`

读作「以甲改乙」：**甲是定本的读法，乙是底本的读法**。

### 为什么不是「补字 + 删字」

`((甲)){{乙}}` 也能写出"加一个甲、删一个乙"，但那表达的是两次独立操作。
校勘上「改」是一次操作，读者需要一眼看出甲乙是同一处异文的两面。
渲染上也因此不同：改字作灰色（低调地给出定本读法），
补字作绿色（醒目地标出新增）。见 §5。

### 生效条件

方括号在 Markdown 里用途很多，所以起止两端都要设卡。

**起始 `[`**：

| # | 条件 | 排除的写法 |
| --- | --- | --- |
| 1 | 不在不生效区内 | 见 §0.1 |
| 2 | 其前不是 ASCII 字母数字 | 指令 label，如 `:jz[…]` |
| 3 | 其前不是 `!`、`[`、`]` | 图片 `![…]`、阙文 `[[…]]`、引用式链接 `…][…]` |
| 4 | 其后不是空白、`]`、`[`、`^` | 任务列表 `[ ]`、空改字、`[[…]]`、脚注 `[^1]` |

**结束 `]`**：

| # | 条件 | 排除的写法 |
| --- | --- | --- |
| 5 | 其前不是空白 | `[ 甲 ]` |
| 6 | 其后不是 `(`、`[`、`:` | 行内链接、引用式链接、链接定义 |

**内容**：

| # | 条件 |
| --- | --- |
| 7 | 非空、不跨行、长度 ≤ 上限、不含 `[` |
| 8 | **至少包含一个 CJK 字符**（可通过 `gzRequireCjk: false` 关闭） |

条件 8 是最后一道保险：它挡掉 `[x]`、`[TODO]`、`[1]` 这类纯 ASCII 的方括号。
需要非 CJK 的改字时，直接写完整指令 `:gz[abc]`。

### 反例

```markdown
[說文](s.html)                 ← 条件 6（行内链接）
[說文][1]                       ← 条件 6（引用式链接）
[說文]: https://example.org     ← 条件 6（链接定义）
![圖](a.png)                    ← 条件 3（图片）
腳註[^1]                        ← 条件 4（脚注）
- [ ] 未完成 / - [x] 已完成      ← 条件 5、8（任务列表）
[[闕文]]                        ← 条件 3、4（预留记号，见 §12）
:jz[孔子也]                     ← 条件 2（指令 label）
```

### 一处已知冲突

**简写式引用链接** `[說文]`（配合别处的 `[說文]: url` 定义）会被识别为改字。
古籍文本里这种写法罕见，且行内链接 `[說文](url)` 不受影响。
确需简写式引用链接时写 `\[說文\]`，或关闭 `gz` 扩展。

### 校勘依据

用 `src` 属性记录改动的依据：

```markdown
:gz[甲]{src=據宋本}:sz[乙]
```

短记号形式不带属性；需要时写完整指令。`bz`、`sz` 同样支持 `src`。

## 5. 校勘三式

补、删、改三种记号合起来，才能把校勘的三种情形分干净：

| 情形 | 写法 | 中间表示 | 渲染 |
| --- | --- | --- | --- |
| **改**：以甲改乙 | `[甲]{{乙}}` | `:gz[甲]:sz[乙]` | 甲**灰色**，乙**红色**加删除线 |
| **删**：单纯删甲 | `{{甲}}` | `:sz[甲]` | 甲**红色**加删除线 |
| **添**：单纯添甲 | `((甲))` | `:bz[甲]` | 甲**绿色** |

三条各有各的颜色，读者不必看上下文就能分辨；
而两个"被删的字"（改字里的乙、单纯删的甲）样式一致，因为它们的性质本来相同——
都是底本有而定本无。

从这三种标记可以机械地还原出两个本子：

* **定本**（校改后）＝ 保留 `bz`、`gz`，丢弃 `sz`
* **底本**（校改前）＝ 保留 `sz`，丢弃 `bz`、`gz`

这也是 [ast.md §3](./ast.md#3-纯文本输出) 规定纯文本输出的依据。

## 6. 抬头（行首 `^`）

表敬的**平抬**：另起一行，且行首比正常行高出 `n` 格。

```markdown
臣某言。
^陛下嗣位以來
^^太祖高皇帝之法
```

→

```markdown
臣某言。
:tt{n=1}陛下嗣位以來
:tt{n=2}太祖高皇帝之法
```

### 生效条件

* `^` 位于**行首**——允许其前有块结构前缀：缩进空白、块引用标记 `>`、
  列表标记（`-` / `*` / `+` / `1.` / `1)`）、ATX 标题标记 `#`；
* 连续 `^` 的个数即抬头级数 `n`（`n ≥ 1`，实现可设上限，建议 9）；
* 该行不在不生效区内。

抬头的**作用范围是本行**：从记号处到行尾（软换行、硬换行或段落结束）为止。
它不会打断段落——`:tt` 是行内标记，渲染器把它到行尾的内容包成一个块级行盒。

需要多行同时抬头时，可直接使用容器形式：

```markdown
:::tt{n=2}
奉天承運
皇帝詔曰
:::
```

抬头是**逐行**的事，所以 `tt` 容器内的源文换行必须保留，
不能像普通段落那样合并成一行——上例应排成两行，各抬二格。

### 反例

```markdown
a ^ b        ← 不在行首，按字面
\^不抬頭      ← 转义，按字面
```

## 7. 空格（行首 `.`）

表敬的**挪抬**：在字前空出 `n` 格，不换行升格。

```markdown
.皇上聖明
..列祖列宗
```

→ `:kg{n=1}皇上聖明` / `:kg{n=2}列祖列宗`

### 生效条件

* `.` 位于行首（前缀规则同 §6）；
* 连续 `.` 的个数即空格数 `n`；
* 该行不在不生效区内。

`^` 与 `.` 可连用，`^` 在前：`^.文` → `:tt{n=1}:kg{n=1}文`。

**行中**需要空格时，直接写指令 `:kg{n=2}`——短记号只在行首生效，
因为句中的 `.` 在西文与数字里太常见。

### 反例

```markdown
一、二。三        ← 全角句号，非 ASCII `.`
\.不空格          ← 转义，按字面
1. 列表项         ← CommonMark 列表标记优先
```

## 8. 专名号 `/…/`

人名、地名、国名、族名、朝代名等专名，排印作专名线（横排下划线，竖排左侧竖线）。

```markdown
/孔子/適/周/，問禮於/老聃/。
```

→ `:zm[孔子]適:zm[周]，問禮於:zm[老聃]。`

`/` 首尾同形，为避免与路径、日期、分数、URL 冲突，条件比其他记号严格。

### 生效条件

**起始 `/`**：

| # | 条件 |
| --- | --- |
| 1 | 不在不生效区内 |
| 2 | 其前为行首、空白，或**非 ASCII 字母数字**的字符（且不是 `:` 与 `/`） |
| 3 | 其后紧接非空白、非 `/` 的字符 |

**结束 `/`**：

| # | 条件 |
| --- | --- |
| 4 | 其前紧接非空白字符 |
| 5 | 其后不是 `/` |

**内容**：

| # | 条件 |
| --- | --- |
| 6 | 非空、不跨行、长度 ≤ 上限、不含 `/` |
| 7 | **至少包含一个 CJK 字符**（可通过 `zmRequireCjk: false` 关闭） |

条件 2 与条件 7 是关键：它们让 `https://example.com/a/b`、`2024/01/02`、
`src/main.ts`、`3/4` 全部落空。

### 可选类型

用属性区分专名种类（渲染器可据此换线型或加 `data-` 属性）：

```markdown
:zm[金陵]{type=地}
```

短记号形式暂不提供类型标注；需要时写完整指令。取值建议：
`人` `地` `国` `族` `朝` `官` `其他`。

### 反例

```markdown
見 https://example.com/a/b     ← 条件 2 失败（`/` 前为 ASCII 字母）
民國 24/5/1                     ← 条件 7 失败（内容无 CJK）
/ 孔子 /                        ← 条件 3、4 失败（紧邻空白）
```

## 9. 书名号 `《…》`

```markdown
《春秋左氏傳》成公十三年
```

→ `:sm[春秋左氏傳]成公十三年`

### 生效条件

* `《` 与 `》` 在同一行，可嵌套（`《漢書《藝文志》》`）；
* 内容非空且长度 ≤ 上限；
* 不在不生效区内。

### 书名号的两种排印

指令的 **label 只保存书名本身**，不含 `《》`；括号是排印选择：

| 渲染选项 | 输出 |
| --- | --- |
| `bookTitleMarks: 'keep'`（默认） | `<span class="guji-sm"><span class="guji-sm-mark">《</span>春秋<span class="guji-sm-mark">》</span></span>` |
| `bookTitleMarks: 'drop'` | `<span class="guji-sm">春秋</span>` |

竖排古籍通常用波浪线代替 `《》`，样式表中直接隐藏 `.guji-sm-mark` 即可。

### 篇名

`《書名·篇名》` 中的间隔号原样保留在 label 内，不再拆分。
需要区分时写两个指令：`:sm[漢書]·:sm[藝文志]`。

## 10. 转义

沿用 CommonMark 的反斜杠转义：`\` 加任一 ASCII 标点，输出该标点本身且**不参与**扩展识别。

| 想写 | 写作 |
| --- | --- |
| `<` | `\<` |
| `((` | `\(\(` |
| `{{` | `\{\{` |
| `[…]` | `\[…\]` |
| 行首 `^` | `\^` |
| 行首 `.` | `\.` |
| `/`（在会误判的位置） | `\/` |

`《》` 不是 ASCII 标点，反斜杠对它无效。要写字面书名号且不加标记，
有两种办法：放进代码片段 `` `《書》` ``，或关闭 `sm` 扩展。

---

## 11. 嵌套与优先级

### 11.1 扫描顺序

同一位置上多个记号都能起始时，按以下优先级（长记号优先，避免 `((` 被拆成两个 `(`）：

```
((   >   {{   >   [[（阙文）   >   《   >   [（改字）   >   <   >   /
```

`□{guess=…}`（[14](#14-缺字猜测guess)）的触发字符 `□` 与其余记号都不冲突，
判定不依赖这个优先级顺序。

### 11.2 嵌套

行内记号可以互相嵌套，内容递归解析：

```markdown
子曰<《論語》/顏淵/篇>
```

→ `子曰:jz[:sm[論語]:zm[顏淵]篇]`

改字与删字的内容同样递归：

```markdown
[《論語》]{{《論语》}}
```

→ `:gz[:sm[論語]]:sz[:sm[論语]]`

### 11.3 与 CommonMark 行内结构的关系

扩展记号与强调、链接、代码片段**平级**，谁先闭合谁生效：

```markdown
**/孔子/**          → **:zm[孔子]**            强调内含专名
[《論語》](x.html)   → [:sm[論語]](x.html)      链接文字内含书名，目标不受影响
```

跨越结构边界的写法（如 `/孔**子/**`）属未定义行为，实现不必保证一致。

### 11.4 与抬头 / 空格的关系

`:tt` 与 `:kg` 是**行首**标记，先于行内扫描被提取；
提取后剩余部分再按行内规则处理。

## 12. 保留与未来扩展

以下记号**保留**，当前版本按字面处理，实现不得赋予其他语义：

| 记号 | 预留用途 |
| --- | --- |
| `〔…〕` | 校勘记引出 |
| `‖` | 原书页码 / 叶次 |
| `%%…%%` | 眉批、旁批 |

`[[…]]` 曾经保留给阙文，**T26 起已生效**，见 [13. 阙文](#13-阙文-)；
不再是"按字面处理"。管道表语法（`\|`）本规范**不使用**（表格另有
[15. 表格容器](#15-表格容器-table)），所以字面 `|` 除 §1「分行」与
§15 表格分格外一律按字面处理，不必反斜杠转义。

新增扩展须同时更新 [directives.md](./directives.md) 的注册表与
[fixtures/cases.json](./fixtures/cases.json)。

## 13. 阙文 `[[…]]`

底本残损、无法辨识的文字——不知道原字是什么，只知道这里缺了字。

```markdown
帝崩，[[]]即位。
[[凡三字，漫漶不可辨]]
```

→

```markdown
帝崩，:qw[]即位。
:qw[凡三字，漫漶不可辨]
```

### 生效条件

* `[[` 与 `]]` 在同一行；
* 内容**允许为空**（`[[]]`，表示"阙了几字、说不清楚"）；含内容时长度 ≤ 上限；
* 不在不生效区内；
* 判定先于改字 `[…]`（见 §11.1 优先级），`[` 前后紧邻 `[`／`]` 时改字本就不起始
  （§4 条件 3、4），两者不冲突。

### 渲染

默认显示为 `□`；有阙文说明（label 非空）时，说明文字保留在
`.guji-qw-label`（默认隐藏），校对模式下切换显示，见
[ast.md §2.6](./ast.md#26-校对模式)。具体缺几个字、每字一个 `□` 还是
一个 `□` 代表"这一段缺"，由整理者按 label 自行说明，本规范不强制字数对应。

### 反例

```markdown
[說文](s.html)     ← 单个 `[`，是改字/链接的范围，不是 `[[`
[[漫漶]{{甲}}       ← `]` 与 `}}` 不配对，`[[` 找不到同行的 `]]`，按字面
```

## 14. 缺字猜测 `□{guess=…}`

`□` 在录入时常表示"这里有字但认不出"，如果 OCR 或整理者对字形有猜测，
用紧跟在 `□` 后面的 `{guess=…}` 记下来。

```markdown
帝崩，太子□{guess=即}位。
```

→ `帝崩，太子:qz{guess=即}位。`

### 生效条件

* **只认紧接在 `□` 后面**、形如 `{guess=X}` 的写法，`X` 不含空白与花括号；
* **不开放通用属性后缀**——这是本记号唯一的形态，不能写
  `□{guess=甲 type=推测}` 这类附加属性，也不能把 `{guess=…}` 挂在
  其他文字或记号后面；
* 判定在同一位置只试这一种形态，不满足就是字面 `□`（不报错）。

### 渲染

默认显示为 `□`；猜测的字保留在 `data-guji-guess` 与 `.guji-qz-guess`
（默认隐藏），校对模式下切换显示猜测字，见
[ast.md §2.6](./ast.md#26-校对模式)。

### 反例

```markdown
□                    ← 后面没有 {guess=…}，就是字面缺字符号
□ {guess=甲}         ← 中间有空格，不是"紧接"，按字面
□{guess=}            ← 取值为空，不匹配，按字面
□{type=推测}         ← 不是 guess 属性，规范不认，按字面
```

## 15. 表格容器 `:::table`

二十四史一类的表格卷（宰相世系表、百官表……）用的容器块，
是 [directives.md](./directives.md#三种指令形态) 里"容器"形态的又一个实例，
写法与既有的 `:::tt{n=2}` 多行抬头同构。定案见
`古籍文本/整体设计/2026-09-表格记法方案.md`（T19/T22 已按此写法转换宋史表格卷）。

```markdown
:::table
!公元 | 紀年 | 宰相進拜加官{2} | 罷免
960 | 建隆元年庚申太祖正月甲辰即位 | 二月乙亥，... | _
961 | 二年辛酉 | 范質{2}^2 | _
_ | 三年壬戌 | ^ | ^
:::
```

### 行列小语法

容器内每一行是一条数据（不像段落那样被合并、软换行必须逐行保留，
理由同 [6. 抬头](#6-抬头行首-)「容器内换行必须保留」）：

| 要素 | 写法 | 说明 |
| --- | --- | --- |
| 表头行 | 整行前加 `!` | 该行所有格渲染为 `<th>`，其余行是 `<td>` |
| 分格 | ` \| `（空格-竖线-空格） | 每行格数不限，但同一格线读者应上下对齐 |
| 空格（这一格确实是空的） | `_` | 与"没写"不同：省略在本记法里是错误，空必须显式写 `_` |
| 跨列（colspan） | 内容后缀 `{n}`，如 `甲{2}` | |
| 跨行（rowspan） | 起格写 `内容{n}^m`（`{n}` 可省，默认 1），它往下续占的行在同一列位置写裸 `^` | `^` 续格标记本身不算一个新格，是"这格已经被上面占住了"的占位 |
| 格内嵌套 | `<…>`／`((…))`／`《…》`／`/…/` 等原样生效 | 整个容器仍在古籍 Markdown 解析范围内，不落入不生效区（这是不选原始 HTML `<table>` 的原因，见方案文档 §二） |
| 格内字面 `\|` | 转义写 `\|` | 分格判定发生在任何行内记号转换之前，见 [§1「分行」](#分行-) |

### 生效条件

* 容器整体是一个 `:::table` … `:::` 块（见 [directives.md](./directives.md)
  的容器语法）；
* 数据行按 ` | ` 切分单元格，`\|` 转义不切分；
* 表头判定只看**整行**第一个字符是否为 `!`，不支持按格单独判定表头。

容器语法本身支持嵌套（`:::table` 可以出现在别的容器里面，如 `:::tt` 之内），
但 book-text 现状用法两者不嵌套（`validate_text_format.py` 的扫描器按此假设
简化实现），不建议写出这种嵌套。

### 渲染

`table` 渲染为 `<table>`，每一"行"渲染为 `<tr>`，
表头行的格渲染为 `<th>`，其余为 `<td>`；`{n}` 对应 `colspan`，
`^m` 对应 `rowspan`；续格 `^` 不产生任何单元格——HTML 原生的
rowspan 语义里，被占住的格本来就不需要再写一个 `<td>`。

### 已知局限

一行如果**所有**格都是续格 `^`（即整行都被上方的 rowspan 占满，
没有一格是真正起格），这一行会因为一个 `<td>`/`<th>` 都没有而在渲染时
整行消失。真实语料里没见过这种情况（§一·3 全量重抓，见方案文档），
出现时建议整理者拆分或调整原表定案。

### 反例

```markdown
甲 | 乙
```

这一行不在任何 `:::table` 容器内，只是普通文字，`|` 不生效——
分格语法只在 `:::table` 容器内部起作用。

## 16. 组字（缺字部件）`:zi[…]`

底本某字缺失，但看得出是由哪几个部件拼成的（版本目录考订、抄本校勘常见），
用组字记下部件与拼法，而不是干脆按 [13. 阙文](#13-阙文-) 处理掉这个信息。

```markdown
令<:zi[⿰句員]>
:zi[上雍下玉]
```

→ `令:jz[:zi[⿰句員]]` ／ `:zi[上雍下玉]`

### 两种写法都认

`:zi[…]` 的内容可以是：

1. **IDS**（Unicode 表意文字描述序列，`⿰`/`⿱`/`⿲`/`⿳`/`⿴`/`⿵`/`⿶`/`⿷`/`⿸`/`⿹`/`⿺`/`⿻`
   等描述符 + 部件），当源材料**明确给出方位**时优先写这种——
   如"左句右員"→`⿰句員`、"上雍下玉"→`⿱雍玉`；
2. **部件方位的文字描述**（如 `上雍下玉`、`三囗，囗中為歹`），
   当拼法复杂到不是简单的两部件横排/竖排（如三部件嵌套）、
   或整理者暂时没能力换算成准确 IDS 时，原样写描述文字。

两种都是合法的 `:zi[…]` 内容，规范不强制二选一，**但同一批转换应当尽量
一致**（都能换算成 IDS 的，不要一部分转一部分不转）。

### 两个部件、没说方位时不要瞎猜

底本常见"甲乙"这样只列两个部件、不说是左右还是上下拼合的写法。
**本规范不提供猜测方位的规则**——`⿰甲乙`（左右）与`⿱甲乙`（上下）
是完全不同的字，猜错比不转更坏。这种情况：

* 人工判读得出方位的，照上面「两种写法都认」写出明确的 IDS 或方位描述；
* 判读不出的，**留原样**（`<甲乙>` 按夹注处理，或按 [13. 阙文](#13-阙文-)
  处理），不要不加方位信息就写 `:zi[甲乙]`——那和到底是 `⿰` 还是 `⿱`
  一样有歧义，不比不转好多少。

批量转换脚本因此只负责**列出候选清单交人决定**，不自动改，
见 `古籍文本/scripts/`（T26 done 单）。

### 渲染

`zi` 渲染为一个 `<span class="guji-zi">`，内容原样输出（IDS 序列或描述文字）。
能否把 IDS 合成出实际字形，取决于渲染环境的字体是否支持 IDC 组字
（如 Source Han Serif 一类不支持，会显示成描述符加两个字的原始序列）；
不支持时的这个原始序列本身也是可读的校勘信息，不算渲染失败。

### 反例

```markdown
:zi[甲乙]      ← 两部件未说明方位，不建议这样写（见上），但语法上仍合法
```

## 17. 图 `:tu[…]` ／ `::tu[…]`

v0.3 起。原书里画的图（卦象、河图、器物），写不成字，就用 `tu` 指向一张裁出来的图。
图片本身不在 Markdown 里：`id` 到同章 fig.json 里查（[09-guji-fig](./09-guji-fig.md)），
说明（label）写图的样子，给读不到图的人和屏幕阅读器看。

```markdown
圖作:tu[左半圈连一实点]{id=f148-2-14}形益恠誕矣
::tu[河圖]{id=p52-fig1}
```

| 形态 | 写法 | 用于 |
| --- | --- | --- |
| 行内 | `:tu[说明]{id=…}` | 图片格：只占一个字的位置的小图形（char 的 `fig` 格） |
| 块级 leaf | `::tu[说明]{id=…}` 单独一行 | 插图块：占几列、半页或整页的图（char 的 `kind: figure` 列） |

leaf 是本规范第一个用到的块级 leaf 形态。它独占一行，会把前后文字切成两个段落；
lines.md 里图列本来就单独一行（[03 §三](./03-guji-markdown.md)），正好对上。

### 生效条件

- 没有短记号，只认指令写法；`figure`、`tupian` 是别名。
- `id` 写法同 fig.json：`[a-z0-9][a-z0-9-]*`。缺了 `id` 仍是合法指令，只是一定显示退回文字。
- 说明可以空（`:tu{id=…}`），可以含别的行内记号，渲染 `alt` 时只取其中文字。

### 渲染

- 渲染器用 `resolveFigure(id)` 选项要图片地址（一般由宿主读同章 fig.json 后给出）。
- 查到：行内是 `<span class="guji-tu">` 里一张 `<img class="guji-tu-img">`，高一个字；
  块级是 `<figure class="guji-tu guji-tu-block">`，宽不超过容器。
- 查不到、或宿主没给 `resolveFigure`：显示 `〔图：说明〕`（说明为空时 `〔图〕`）。
  `〔…〕` 在源文里是保留记号（§12），这里只出现在渲染结果中，不冲突。
- 纯文本输出为 `□`，检索跳过，同阙文（[ast.md §3](./ast.md#3-纯文本输出)）。

### 反例

```markdown
:tu[河圖]{id=p52-fig1}后面接字     ← 语法合法，但插图块应单独一行写成 ::tu
::tu[卦]{id=a} 乙                  ← leaf 后面还有字：不成 leaf，按字面输出
```
